Google Drive Integration Setup

Enable secure vendor-to-client photo/video delivery through the client's shared Google Drive folder — for this client and every client after. Follow Steps 1–5 once per client project.

How it works. The app uploads photos using a service account (a machine identity) from a Google Cloud project. The service account acts like a member of your Drive, but it can only write into a shared drive — it has no storage quota in a personal "My Drive", so client folders must live inside a shared drive and the shared drive itself is shared with the service account once. Any upload the app makes is then instantly visible to everyone the folders are shared with (client, vendor, and you). One service account + one shared drive can serve all clients.
1

Google Cloud project + service account + key

The service account is your "upload robot." The key file is its ID badge — keep it private.

1a. Pick the Google Cloud project

  • Go to console.cloud.google.com and sign in with the agency Google account.
  • If you already have a project used for the agency (e.g. vibe-coding-whoisdesir), select it in the top project picker and use it.
  • Otherwise create one: project picker → New Project → name it e.g. whoisdesir-media → Create.
  • Note the Project ID (you'll see it in the header / URLs). Keep it handy for Steps 1b and 2.

1b. Create the service account

  1. Open IAM & Admin → Service Accounts: console.cloud.google.com/iam-admin/serviceaccounts (replace PROJECT_ID).
  2. Click + Create service account.
  3. Name: widmedia-drive-upload (or similar). Click Create and Continue.
  4. Grant it a role — none needed for Drive (permissions come from folder sharing). Just click Done.

1c. Download the JSON key

  1. In the service account list, click the widmedia-drive-upload account.
  2. Go to the Keys tab → Add Key → Create new key → choose JSON → Create.
  3. A file like widmedia-drive-upload-XXXX.json downloads automatically. Save it in a safe, private place. You will never see the private key again once the file is closed.
  4. Open the file and copy two values (the client_email and the private_key):
{
  "type": "service_account",
  "project_id": "PROJECT_ID",
  "client_email": "widmedia-drive-upload@PROJECT_ID.iam.gserviceaccount.com",   ← copy this
  "private_key": "-----BEGIN PRIVATE KEY-----\nMIIEvQIB...\n-----END PRIVATE KEY-----\n"   ← copy this
}
Getting a "fresh key" for an existing service account: open the service account → Keys tab → Add Key → Create new key → JSON. This regenerates a new private key (old ones are invalidated when deleted). This fixes the invalid_grant: Invalid JWT Signature error.
2

Enable the Google Drive API

Turns on the Google Drive API for this project. Required once per project.

  1. Open the Drive API page for your project: console.developers.google.com/apis/api/drive.googleapis.com/overview (replace PROJECT_ID).
  2. Click Enable.
  3. Wait 1–2 minutes for it to propagate.
If you see: Google Drive API has not been used in project ... before or it is disabled — that means this step wasn't done (or was done in the wrong project). Enable it and retry.
3

Create a shared drive and put client folders inside it

Service accounts can't upload into a personal "My Drive" — they can only write into a shared drive. Do this once for the agency; then every client folder lives inside it.

3a. Create the shared drive (once)

  1. In Google Drive (agency account) → left sidebar → Shared drives → + New.
  2. Name it e.g. WhoisDesir Media → Create.

3b. Put each client folder inside the shared drive

  1. Create new client folders inside the shared drive (e.g. /Shared drives/WhoisDesir Media/<Client Name>/Photography).
  2. If a folder already exists in My Drive: right-click → Organize → Move → pick the shared drive. The folder keeps its ID, so all existing links keep working.

3c. Share the shared drive with the service account

  1. Open the shared drive → Share (top right).
  2. In Add people and groups, paste the service account email: widmedia-drive-upload@PROJECT_ID.iam.gserviceaccount.com
  3. Set permission to Content manager → Send. Membership applies to every folder inside the shared drive.
Viewer

Clients can open and play photos/videos — solves the "can't open the video" issue.

Content manager

Give the service account this role on the shared drive so the app can upload everywhere inside it.

Restricted

Avoid — forces sign-in and blocks embedded previews.

Also set each client folder's General access → Anyone with the link → Viewer so clients and vendors can open files without signing in.

4

Add the credentials to the app

Put the two values from Step 1c into the environment so the upload API can authenticate.

4a. Local development (.env)

In the project root .env file:

GOOGLE_SERVICE_ACCOUNT_EMAIL="widmedia-drive-upload@PROJECT_ID.iam.gserviceaccount.com"
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEvQIB...\n-----END PRIVATE KEY-----\n"
  • Keep the key on a single line with line breaks written as \n.
  • .env is git-ignored — never commit it.
  • Restart the dev server after editing.

4b. Production (Vercel)

  1. Open the project in vercel.com → Settings → Environment Variables.
  2. Add the same two variables for the Production environment (and Preview/Development if needed):
NameValue
GOOGLE_SERVICE_ACCOUNT_EMAILservice account email (client_email)
GOOGLE_PRIVATE_KEYprivate key, single line with \n escapes
  1. Click Save, then redeploy (or push to trigger an auto-deploy).
Tip: Storing the full JSON is supported too — set GOOGLE_APPLICATION_CREDENTIALS_JSON to the entire contents of the key file instead.
5

Verify the upload

Confirm end-to-end that photos reach the client's shared folder.

  1. Log in as a vendor (contractor) → open the project → Deliver Photos to Client Drive.
  2. Pick the linked Google Drive folder, select a few photos, click Upload Photos to Drive.
  3. Expected: a green confirmation with the file count.
  4. Open the folder in Google Drive and confirm the files are there, then log in as the client and confirm they can open them in the Media Gallery.

Troubleshooting

503 — "Google Drive is not configured yet."
The env vars are missing (Step 4).
403 / permission error on upload.
The folder isn't inside a shared drive the service account belongs to (Step 3).
"Service Accounts do not have storage quota."
The target folder is in My Drive, not a shared drive. Move it into the shared drive (Step 3b).
The folder listing is empty after moving.
App API calls use supportsAllDrives — if it's still empty, re-check that the shared drive is shared with the service account.
invalid_grant: Invalid JWT Signature.
The private key is stale or mis-escaped. Regenerate it (Step 1c) and re-copy it as a single line with \n.
Drive API disabled error.
Enable the API in the correct project (Step 2) and wait 1–2 minutes.
Client can't open a video.
Folder must be Anyone with the link → Viewer, and the video must finish processing in Drive before sharing.
✓

Per-client checklist (run once per new client)

  • Create the client's media folder(s) inside the shared drive (e.g. Photography, Videos).
  • Share the shared drive with the service account as Content manager (once per shared drive).
  • Set each folder's General access → Anyone with the link → Viewer so clients can preview without signing in.
  • In the admin portal: Clients → Media Gallery/Folders → link each folder's ID or URL.
  • Assign the project to a vendor (contractor) so they see it and the upload section.
  • Have the vendor upload a test photo; confirm it appears in Drive and in the client portal.

Remember: the service account and Google Cloud setup (Steps 1–2) are done once for the agency. Every new client only needs Steps 3–5.
